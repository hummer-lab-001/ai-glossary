01

Claude Codeを理解する核心の用語

Claude Codeを使う上で、最初に押さえておきたい7つの言葉。これだけで全体像が見えます。

7 TERMS
⚒️
Claude Code
Claude Code

Anthropic公式の、AIエージェント機能付き開発ツール。ファイル操作・コード作成・実行までこなす。

通常のClaude（チャット型）が「会話する相手」だとすると、Claude Codeは「実際に手を動かす助手」。あなたのPC上のファイルを読み・書き・実行し、必要なら外部ツールも使ってくれます。開発者向けですが、最近は「コードを書かない人」でも使える場面が増えています。

「Claudeとチャットで相談する」から「Claudeに実作業を任せる」へ進む、ちょうどその橋渡しになるのがClaude Codeです。
🧠
コンテキストウィンドウ
Context Window

AIが今の会話で「一度に覚えていられる」情報量の上限のこと。

人間も一度に分厚い本を10冊同時に読めないように、AIにも処理できる情報量の限界があります。これがコンテキストウィンドウ。会話が長くなったり、巨大ファイルを読ませると、古い内容から忘れていく仕組みです。Claude Opus 4系では数十万トークン規模に拡張されています。

「最初に伝えた前提をClaudeが忘れている」と感じたら、コンテキストが一杯になっている合図。要約コマンドで圧縮するか、新規セッションを始めましょう。
🔢
トークン
Token

AIが文章を処理するときの最小単位。料金・速度・記憶量がすべてこれで決まる。

人間は「文字数」で考えますが、AIは「トークン数」で考えます。日本語だとざっくり1文字あたり1〜3トークンくらい（文字の種類で変動）。Claude Codeを使うと、「いまセッションで何トークン使ったか」が表示されるので、長文を扱う時は意識しておくと良いでしょう。

「このAIは100万トークン対応」と言われたら、「日本語でざっくり原稿用紙1,000枚分を一気に処理できる」とイメージすればOKです。
💬
セッション
Session

Claude Codeを起動してから終了するまでの「1回の作業」のかたまり。

1セッションの中ではClaudeが会話の流れを覚えています。セッションを閉じると、原則として会話の記憶はリセット（ただしメモリ機能で重要情報は引き継がれます）。プロジェクトファイル自体は残るので、次のセッションでもファイルからは状況把握ができます。

「Claudeが急に話の流れを忘れた」「文脈がぐちゃぐちゃになってきた」と感じたら、思い切ってセッションを切り替えるのが正解です。
⚙️
モデル
Model

Claudeの「頭脳」のグレード違い。性能・速度・料金の組み合わせで選ぶ。

Claudeには Opus（最高性能・じっくり）、Sonnet（バランス型・万能）、Haiku（高速・軽量）の3系統があります。難しい設計やコード生成はOpus、ざっと整理する作業はHaikuのように使い分けると、時間と料金の両方が節約できます。Claude Codeでは /model コマンドで切り替え可能。

「常にOpusで使う」は富裕層の贅沢な使い方。賢く使い分けることで、月の請求が大きく変わってきます。
🤔
拡張思考
Extended Thinking

Claudeが回答する前に「内部でじっくり考える」ステップを挟むモード。

複雑な問題に対して、いきなり答えを書き始めるのではなく、段階的に推論してから回答する機能。数学の「途中式」を頭の中で書くイメージです。Claude Codeでは「Thinking...」表示中にこの拡張思考が動いています。回答の精度が上がる代わりに、少し時間がかかります。

バグの原因究明、複雑なロジック設計、論理が必要な意思決定など、ミスが許されない作業ほど拡張思考の真価が発揮されます。
🔧
ハーネス
Harness

AIモデルを「実際に仕事ができる状態」にする外側の仕組み全体。Claude Code自体がハーネス。

Claude（AIモデル）はそのままでは文章を返すだけ。これにファイル操作・コマンド実行・Web検索などのツール、許可管理、記憶機能を装着して、実際に作業できるエージェントに仕立てた装置がハーネスです。Claude Code、Cursor、Cowork、Managed Agentsはすべてハーネスの仲間。デスクトップ版もVS Code版もCLI版も、外見は違っても中身のハーネスは同じです。

2026年AI業界の最大の競争領域。「どのモデルか」より「どのハーネスで動かすか」のほうがビジネス成果を左右します。
02

Claude Codeを動かす環境

同じClaude Codeでも、使う「場所」はいろいろ。自分のスタイルに合った環境を選ぼう。

6 TERMS
🖥️
デスクトップアプリ
Desktop App

インストールするだけで使える、一番手軽なClaude Code環境。

日本語UIで操作が分かりやすく、設定もほぼ不要。初めてClaude Codeに触れる人の入口として最適です。Macなら .dmg、Windowsなら .exe を公式サイトからダウンロードしてインストール。最近はCowork機能（バックグラウンド作業）の追加で、非エンジニアにも使いやすくなりました。

「とりあえずClaude Codeを試してみたい」「ターミナルは怖い」という人は、迷わずデスクトップアプリから始めましょう。
⌨️
CLI（コマンドライン版）
Command Line Interface

ターミナルから文字だけで操作する、Claude Codeのオリジナル形式。

マウスやボタンを使わず、キーボードだけで完結する操作方式。ターミナル（Macの場合）またはコマンドプロンプト・PowerShell（Windowsの場合）から claude と打つだけで起動します。慣れると圧倒的に速く、自動化との相性も抜群。本格的にコーディングする人にはこちらが定番。

「マウスを動かす時間がもったいない」「シェルスクリプトと組み合わせたい」というレベルになったら、CLIに進化するタイミングです。
🧩
VS Code拡張
VS Code Extension

世界一使われているコードエディタに、Claude Codeを組み込む拡張機能。

VS Code（Visual Studio Code）はMicrosoftが提供する人気No.1のコードエディタ。これにClaude Codeの拡張機能を入れると、コードを書きながら横でClaudeに相談できる開発環境が完成します。プログラミングを本格的にする人には、最強の組み合わせの1つ。Cursorも同系統の選択肢です。

「日常的にコードを書く」人なら、VS Code＋Claude Code拡張で生産性が一段上に。書きながら相談、レビュー、リファクタリングがシームレスに行えます。
🌐
Webアプリ版
Web App

ブラウザだけで動く、インストール不要のClaude Code。

claude.ai/code にアクセスすれば即使えます。クラウド上で実行されるので、自分のPC環境に左右されないのがメリット。会社のPCにソフトを入れられない、外出先のサブPCで使いたい、といった場面で重宝します。ファイルもクラウド上で扱うので、PCを変えても続きから作業できます。

「環境構築に手間をかけたくない」「複数のPCを行き来する」人にぴったり。ただし機微な情報を扱う場合はセキュリティ要件を確認しましょう。
🛠️
IDE（統合開発環境）
Integrated Development Environment

コードを書く・実行する・デバッグするが、ひとつのソフトで全部できる「作業台」。

プログラミングに必要な道具がまとまったソフトウェアの総称。VS Code、JetBrains（IntelliJ・PyCharm等）、Eclipse、Xcodeなどが代表例。Claude CodeをIDEと組み合わせると、「AIアシスタント付きの作業台」になります。コードを書く・読む・直すという日常作業が、ぐっと楽になります。

エンジニアの会議で「IDEで開いて」と言われたら、「VS Code等でファイルを開いてくれ」という意味だと理解しておけば大丈夫です。
🤝
Cowork（コワーク）
Claude Cowork

Claudeに作業を「お願いしておく」感覚で任せられる、バックグラウンド作業機能。

通常のチャットがリアルタイム会話なら、Coworkは「指示を渡して、別の仕事をしている間にClaudeに自律的に進めてもらう」形式。終わったらPCやスマホに通知が届きます。デスクトップアプリの目玉機能で、2026年4月にGA（一般提供）化されました。Pro/Maxプラン以上で利用可能。

時間のかかる調査・下書き・大量データ処理など、「今すぐ返事はいらないけど、終わったら知りたい」作業を任せる用途で威力を発揮します。
03

Claude Codeの主要機能と操作

Claude Codeを使いこなすうえで、出会う頻度が特に高い機能と操作の言葉。

10 TERMS
📋
CLAUDE.md
CLAUDE.md

Claude Codeへの「取扱説明書」。プロジェクトのルールを書いておく特別なファイル。

プロジェクトのルートフォルダに CLAUDE.md という名前で置くと、Claude Codeが毎回最初に読んで、その指示を守ってくれます。「日本語で回答」「テストを必ず実行」「特定のコーディング規約に従う」など、繰り返し伝えたい指示はここに集約。/init コマンドで雛形が自動生成されます。

「毎回同じ前提を伝えるのが面倒」「チーム全員に同じやり方をさせたい」というとき、CLAUDE.md があれば一発解決。
⚡
スラッシュコマンド
Slash Command

「/」で始まる、Claude Code操作用のショートカット命令。

チャット欄に /help、/model、/compact などと打つと、Claude Codeの設定変更や特殊操作ができます。SlackやNotionで使われるスラッシュコマンドと同じ発想。困ったら /help と打てば使えるコマンド一覧が出てきます。

毎回マウスで設定画面を開かなくても、サッと操作したいとき。慣れるとキーボードだけで快適に作業できます。
🔒
パーミッション（権限）
Permission

Claude Codeに「何をしていいか」を決める、安全装置としての許可設定。

Claude Codeがファイルを編集したりコマンドを実行したりする前に、「これやっていいですか？」と確認を求めてくる仕組み。許可（Allow）か拒否（Deny）を選びます。うっかり大事なファイルを壊さないための保険であり、自由度と安全のバランスを取る要です。

慣れてくると毎回の確認が面倒に感じますが、「自動許可」を選ぶ前に必ず内容を理解してから設定を変えましょう。
🏖️
サンドボックス
Sandbox

Claude Codeが安全に動くための「砂場」。決められた範囲内でしか動かない隔離環境。

子どもが砂場の中だけで自由に遊ぶように、Claude Codeも決められた範囲の中で動作します。これがあるおかげで、PCのシステムファイルを書き換えてしまうような事故が起きません。Vol.03で紹介するManaged Agentsのサンドボックスは、この概念をクラウドで本格化したものです。

「AIに勝手にPCをいじられるのが怖い」という不安に対する、技術的な答えがこのサンドボックスです。
📝
プランモード
Plan Mode

いきなり実行せず、「まず計画を見せて」とClaudeに依頼するモード。

Claude Codeが「こういう手順でやろうと思いますが、いいですか？」と計画を提示してくれます。内容を見てからGOを出せるので、安心して大きな変更が依頼できます。ヘッダ部分などで切り替え可能。慎重に進めたいときの必須機能です。

「大規模な変更を任せたいけど、中身を確認してから進めたい」というとき、プランモードを使うと事故率がぐっと下がります。
💾
チェックポイント
Checkpoint

作業の途中で自動的に作られる「セーブポイント」。失敗してもここまで戻れる。

ゲームのセーブと同じで、Claude Codeが作業を進める途中で自動的にチェックポイントが記録されます。「やっぱり気に入らない」「壊れた」「巻き戻したい」というとき、ここまでサッと戻れる安心機能です。Git の commit よりもっと細かい単位での「やり直し」が可能。

大胆にAIに任せる挑戦的な使い方ができるのは、このチェックポイントがあるからこそ。失敗を恐れずに試せます。
🔍
差分ビュー
Diff View

変更前と変更後の違いを「色付き」で見せてくれる表示機能。

Claude Codeがファイルを変更すると、赤色で削除された箇所、緑色で追加された箇所を表示してくれます。これにより「Claudeが具体的に何をしたのか」が一目瞭然。承認する前の確認に欠かせない機能です。

変更を確認するとき、ファイル全体を読み直す必要はありません。色がついた行だけ見れば差分が把握できます。
🗜️
コンパクト
/compact

長くなった会話を要約してコンテキストの空きを作る、便利なコマンド。

会話が長くなりコンテキストウィンドウが一杯に近づくと、Claudeの反応が遅くなったり、古い話を忘れたりします。/compact と打つと、これまでの会話を要点だけに圧縮して、新しい話のための空きスペースを確保してくれます。

長時間セッションで「最初の指示を忘れてきた」と感じたら、迷わず /compact。リセットせずに続けられます。
🤖
ノンインタラクティブモード
Non-interactive Mode

人間が操作しなくても、Claudeが自動で動く「丸投げ」モード。

CLIで claude -p "〇〇して" のように使います。対話なしで指示を渡してClaudeに自動処理させるモードで、定期実行のスクリプトやバッチ処理に組み込めます。「毎朝7時にレポートを生成してSlackに投稿」のような自動化が可能になります。

「毎日決まった作業をAIにやらせたい」という発想が出てきたら、このモードの出番です。cron や Task Scheduler と組み合わせて使います。
🧩
自動メモリ
Auto Memory

Claudeが大事な情報を自分で記録して、次のセッションでも覚えていてくれる機能。

「私は営業部です」「ファイル名は英語で」など、一度伝えた重要情報をClaudeが自動的に記録してくれます。別のセッションを始めても、これらの情報を参照して話を進めてくれるので、毎回自己紹介や前提共有をする必要がありません。設定で記憶内容の確認・編集も可能。

「同じことを毎回説明するのが面倒」を解消する機能。使い続けるほど、自分専用のアシスタントに育っていきます。
04

拡張・連携の仕組み

Claude Codeを「もっと自分仕様」にしていくための、拡張機能の言葉たち。

8 TERMS
🔌
API
Application Programming Interface

ソフトウェア同士が「やりとりする窓口」。AIと外部サービスをつなぐ基本の仕組み。

レストランで言えば「注文カウンター」のようなもの。アプリ（お客さん）がカウンター（API）に注文を出すと、厨房（サーバー）が料理（データ）を返してくれる。Claude Codeも裏側ではClaude APIを通じてAnthropicのサーバーとやりとりしています。自社サービスにAIを組み込むときも、APIが基本の入口になります。

「API連携する」と言われたら、ソフト同士を自動でつなぐ仕組みの話だと思えばOK。エンジニアでなくても押さえておきたい基本語。
🔗
MCP
Model Context Protocol

Claude Codeをあらゆる外部ツールにつなげる「共通規格」。AI界のUSB。

USB規格があるおかげで、どのメーカーの機器も互換性があるように、MCPはClaudeとあらゆるサービス（Slack、Notion、GitHub、データベース等）を共通ルールで接続できる仕組みです。Anthropic発祥ですが業界標準化が進んでおり、2026年AI連携の土台になっています。

「うちのサービスをClaudeから操作したい」と思ったら、まずMCP対応を検討するのが2026年の標準的なアプローチです。
🖧
MCPサーバー
MCP Server

外部サービスのツールをClaude Codeに「公開する」プログラム。

「Notion用MCPサーバー」を設定すると、Claude CodeからNotionのページを直接読み書きできるようになります。Slack用、GitHub用、Google Drive用、データベース用など、世界中の開発者がさまざまなMCPサーバーを公開中。インストールしていくほど、Claude Codeの「できること」が増えていきます。

「MCPサーバーを追加する」＝Claude Codeに新しいツールとの接続口を増やすこと。Claude Codeのカスタマイズの中核です。
⚙️
フック
Hook

「〇〇のときに自動で△△する」という、条件付き自動処理の仕掛け。

ドアが開いたら電気がつく、のような自動化の仕組み。Claude Codeでは「ファイル保存時に自動フォーマット」「コマンド実行前に安全チェック」「セッション終了時にログ保存」といった処理を、特定タイミングで挟めます。2026年時点で18種類以上のフックが用意されています。

「毎回手動でやっている確認・整形作業」をなくしたいとき、フックの導入を検討するタイミングです。
🥷
スキル
Skill

定型作業を「型」として登録しておく、Claude Code版の必殺技。

「議事録を作成する」「コードレビューする」「スライドを生成する」など、繰り返し使う作業手順をパッケージ化したもの。.claude/commands/ フォルダにmarkdownで書いておくと、スラッシュコマンドとして呼び出せます。自分の仕事に合ったオリジナルスキルを蓄積していけば、Claudeが「自分専用のアシスタント」に育ちます。

同じパターンの作業が多い人ほど効果絶大。スキルが10個揃ったあたりで、明らかに作業効率が変わってきます。
🎮
プラグイン
Plugin

スキルやフックなどをまとめた、Claude Code版「拡張パック」。

スマホにアプリを入れて機能を増やすように、Claude Codeにもプラグインを追加して用途特化の能力一式を組み込めます。「Web開発用プラグイン」「データ分析用プラグイン」のように、特定の業務向けに最適化されたスキル群がまとまっています。

「〇〇用プラグインを入れる」＝Claude Codeに新しい専門能力を一気に追加するということ。素早く特化型に進化させたいとき便利。
👥
サブエージェント
Subagent

メインのClaudeが「分身」を生み出して、並行作業させる仕組み。

複雑な作業のとき、Claude Codeが自分の分身（サブエージェント）を作って並列で動かすことがあります。「調査担当」「実装担当」「レビュー担当」など、それぞれが独立した作業スペースで動くので、お互いの作業を邪魔しません。Vol.03で詳しく扱うマルチエージェント・オーケストレーションの基礎概念です。

画面上で「Agent」と複数の処理が同時に走っているのを見たら、サブエージェントが活躍しているサインです。
🏢
エージェントチーム
Agent Team

複数のエージェントが役割分担してチームを組み、協力して動く仕組み。

サブエージェントの発展形です。それぞれに役割（リサーチ・実装・テスト・レビュー等）を与え、人間のプロジェクトチームのように協働させるのがエージェントチーム。1人で全部やるより、専門分業のほうが速くて品質も高い——という、人間の組織論と同じ原理が働きます。

大きなプロジェクトを「調査→実装→テスト→ドキュメント化」と一気に進めたいとき、エージェントチームの設計が活きてきます。
05

ファイル操作の基礎知識

PCのファイル構造を理解すると、Claude Codeが「何をしているか」が劇的に分かりやすくなります。

7 TERMS
☁️
ローカル / クラウド
Local / Cloud

ローカル＝あなたのPC内、クラウド＝インターネット上のサーバー。

「ローカルで動く」とは自分のPC上でソフトが動くこと。Claude Codeのデスクトップ版・CLI版はローカル動作です。一方、「クラウド」はインターネット上のサーバーで動くこと。Web版のClaude Codeはクラウド動作です。データの保管場所も同様の区別があります。

「ローカルのファイルを編集して」＝「自分のPC内のファイルを編集して」という意味。クラウドのファイルを扱うときは認証や同期の話が出てきます。
📁
ディレクトリ / フォルダ
Directory / Folder

ファイルを整理して入れる「箱」。フォルダと同じ意味で、エンジニア界隈ではディレクトリと呼ぶ。

Windows・Macで普段「フォルダ」と呼ぶものと完全に同じもの。ターミナルやプログラミングの世界では「ディレクトリ」と呼ぶのが慣例です。Claude Codeが「ディレクトリ」と言ったら、「あ、フォルダのことね」と頭の中で読み替えれば大丈夫。

「このディレクトリにファイルを作成しました」＝「このフォルダにファイルを作りました」。意味は同じ、呼び方が違うだけです。
🗺️
パス
Path

ファイルやフォルダがPC内のどこにあるかを示す「住所」。

ファイルが置いてある場所を示す文字列です。Macでは /Users/taro/Documents/report.txt のように、フォルダ名を「/」でつないで表現します。Windowsでは「\」（バックスラッシュ）が使われます。Claude Codeとのやりとりで頻出するので、自分のPCの基本パスは把握しておくと便利。

Claude Codeが「ファイルのパスを教えて」と聞いてきたら、ファイルの場所（住所）を伝えればOK。エクスプローラーやFinderからコピーできます。
🏠
ホームディレクトリ
Home Directory (~)

自分のユーザーフォルダ。「~」（チルダ）は「自分の家」を意味する記号。

~（チルダ）はホームディレクトリの省略記号。Macなら /Users/あなたの名前/、Windowsなら C:\Users\あなたの名前\ のことを指します。~/.claude/ と書いてあったら、「自分のホームフォルダの中の .claude フォルダ」という意味。

Claude Codeの設定ファイルは ~/.claude/ に保存されます。「~」を見たら「あ、ホームのことね」と読み替えればOK。
📍
カレントディレクトリ
Current Directory

今いるフォルダ、つまり「現在地」のこと。

ターミナルやClaude Codeは常にどこかのフォルダに「いる」状態です。その今いる場所がカレントディレクトリ。./ は「今いるフォルダ」を指す省略記号で、../ は「1つ上のフォルダ」を指します。Claude Codeを起動したフォルダがカレントディレクトリになります。

Claude Codeが「カレントディレクトリに作成しました」と言ったら、「今開いているプロジェクトのフォルダにファイルを置いた」ということ。
👻
ドットファイル / 隠しファイル
Dotfile

「.」で始まる名前のファイルやフォルダ。通常は非表示。

.claude/ .gitignore のように、名前が「.」（ドット）で始まるファイルは設定用の特別なファイルとして扱われ、通常のエクスプローラーやFinderでは表示されません。Claude CodeのCLAUDE.mdや各種設定は、この隠しフォルダの中に入っています。

「.claudeフォルダが見つからない」と思ったら、エクスプローラー・Finderの「隠しファイルを表示」をオンにしてみましょう。
🏷️
拡張子
File Extension

ファイル名の末尾につく「.md」「.html」などの目印。ファイルの種類を示す。

ファイルの種類を示すラベルです。.md はMarkdown（文書）、.html はWebページ、.js はJavaScript（プログラム）、.py はPython（プログラム）。Claude Codeはこの拡張子を見てファイルの中身を判断し、適切な処理をします。

「.mdファイルを作成しました」と言われたら、Markdown形式のテキストファイルが作られたということ。中身は普通の文字なのでメモ帳でも開けます。
06

Gitとバージョン管理の基本

Claude Codeを使っていると必ず出会う「Git」。概念だけ押さえておけば、Claude Codeの動きが見えてきます。

10 TERMS
📜
Git（ギット）
Git

ファイルの変更履歴を全部記録・管理してくれるシステム。失敗しても元に戻せる安心装置。

Wordの「変更履歴の記録」を、もっと強力にしたようなもの。「いつ・誰が・何を・なぜ変えたか」がすべて記録されます。間違えても過去の状態にいつでも戻せるので、安心して大胆な変更ができます。世界中の開発者がほぼ全員使っている標準ツール。

Gitで管理しているプロジェクトなら、Claude Codeが何を変えたかも履歴として追えるので、より安心して任せられます。
🏛️
リポジトリ
Repository

Gitで管理されたプロジェクトの「倉庫」。略して「リポ」とも呼ばれる。

プロジェクトのファイル一式と、その変更履歴のすべてが入った場所です。1つのプロジェクト＝1つのリポジトリ、と考えてOK。GitHubに置けば「リモートリポジトリ」、自分のPC内なら「ローカルリポジトリ」と呼びます。

「このリポジトリを開いて」＝「このプロジェクトのフォルダを開いて」と同じ意味。エンジニアと話すときの基本語です。
📋
クローン
Clone

リポジトリをまるごと自分のPCにコピーすること。

インターネット上（GitHub等）にあるプロジェクトを、自分のPCにダウンロードして手元で作業できるようにすること。ファイルだけでなく、変更履歴もまるごとコピーされるのがポイント。これにより、オフラインでも作業できますし、過去のどの時点にも戻れます。

「まずリポジトリをクローンして」＝「プロジェクトを手元にダウンロードして」ということ。Claude Codeでの作業の最初の一歩。
💾
コミット
Commit

変更内容を「確定保存」する操作。ゲームのセーブのようなイメージ。

ゲームの「セーブ」と同じ感覚ですが、Git のコミットでは変更内容のメモ（コミットメッセージ）も一緒に残すのが特徴。「ログイン画面のデザインを変更」「バグFix #123」のように、後から見て分かるメモを残すのがコツです。

Claude Codeが「コミットしますか？」と聞いてきたら、「ここまでの作業をセーブしますか？」という意味。基本的にこまめにコミットしましょう。
🌿
ブランチ
Branch

本線から枝分かれした「作業用の別ライン」。本番を壊さず新機能を試せる。

本番環境（mainブランチ）を直接いじらず、別の枝（ブランチ）を作って安全に試す仕組み。完成したら本線に合流させます。木の幹から枝が分かれて、また幹に戻ってくるイメージ。チーム開発ではこの仕組みが必須です。

「新しいブランチを切って作業して」＝「本線とは別の場所で安全に作業して」ということ。Claude Codeに大きな変更を任せるときも、ブランチを切るのが定石。
🔀
マージ
Merge

分岐したブランチを本線に「合流」させる操作。

ブランチで作った新機能が完成したら、本線（mainブランチ）に取り込みます。これがマージ。もし本線側も変更されていて矛盾（コンフリクト）が起きたら、どちらを優先するか人間が判断する必要があります。Claude Codeはコンフリクト解消も手伝えます。

「マージする」＝「完成した作業を本番に反映する」こと。リリースの最終段階で出てくる言葉です。
🔄
プッシュ / プル
Push / Pull

プッシュ＝サーバーにアップロード、プル＝サーバーからダウンロード。

プッシュは自分のPCの変更をサーバー（GitHub等）に送ること。プルはサーバーの最新状態を自分のPCに取り込むこと。チームで作業するとき、この2つで全員の変更を同期します。1人で作業しているときも、バックアップのために定期的にプッシュするのが安心です。

「プッシュしておいて」＝「変更をクラウドに上げておいて」。「プルしてから作業して」＝「最新版を取り込んでから始めて」。
🚫
.gitignore
.gitignore

「Gitで管理しなくていいファイル」を指定するリスト。事故防止の要。

パスワード・APIキー・一時ファイル・巨大なログなど、Gitに記録したくない・公開したくないものをリストアップしておくファイル。ここに書いたファイルは Git が無視してくれます。.env のような秘密情報ファイルを誤ってGitHubに公開する事故を防ぐ、めちゃくちゃ重要な仕掛けです。

「パスワードがGitHubに漏れた」という事故は、ほぼ100%このファイルの設定漏れが原因。新規プロジェクトでは必ず最初に整備を。
🐙
GitHub
GitHub

Gitリポジトリをインターネット上で共有・管理できる、最大手のサービス。

Gitが「変更履歴管理の仕組み」だとすると、GitHubはそれをクラウドで共有できる場所。世界中の開発者が利用する「コードのSNS」のような存在で、企業の開発インフラとしても定番。GitLab、Bitbucketも同系統のサービスです。

Claude Codeで作ったコードをチームと共有するときも、自分のPCのバックアップとしても、GitHubは最重要インフラ。
📬
プルリクエスト（PR）
Pull Request

「この変更を本番に入れていいですか？」と仲間にレビュー依頼を出す仕組み。

いきなり本番に変更を入れず、まず「こういう変更をしました。確認してください」と提案する仕組み。チームメンバーが内容を確認（レビュー）してOKを出してから、初めてマージされます。エンジニアの世界では基本マナーで、Claude Codeもプルリクエスト作成を補助できます。

「PR出しておいて」＝「変更内容をレビュー依頼として提出して」という意味。チーム開発の品質を守る重要プロセスです。

用語を知ることが、自由度を広げる

この用語集に書かれていることを全部理解してから使い始める必要はまったくありません。

「MCPでNotionと連携したい」「APIを使って自動化したい」と思ったとき、自分ですべて調べる必要はありません。GitHubのリポジトリURLをClaude Codeに渡して、日本語で「これを使えるようにして」と伝えれば、セットアップまでやってくれます。

でも、用語を知っていると「Claudeが今、何をしているか」が見えるようになり、より的確な指示が出せるようになります。これがVol.01〜Vol.03の3冊で目指している、AIとの新しい関係性です。
