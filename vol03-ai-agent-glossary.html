この用語集の使い方

この用語集は、AIを「使う側」から「作る側」へ一歩進みたい人のためのものです。

01

AIエージェント時代の基本概念

「AIエージェント」というキーワードを聞いたら、まず押さえておきたい基本のき。

8 TERMS
🤖
AIエージェント
AI Agent

「目的を伝えたら、AIが自分で計画して、自分で動いて、結果を出す」自律型AIのこと。

これまでのAIが「質問に答える」だけだったのに対し、エージェントはファイルを開いたり、ツールを使ったり、判断したりを自分で連続的にやります。「議事録を要約して関係者に送って」と一言伝えれば、要約・宛先選定・送信まで自走するのが理想型。Claude Code、Cowork、Managed Agentsもすべてエージェントの一種です。

「AI活用」の次の段階。クライアントに提案するとき、単なるチャット利用ではなく「AIエージェント導入」と言えるかで、提案の重みが変わります。
🔧
ハーネス
Harness

AIモデルを「実際に仕事ができる状態」にするための、外側の仕組み全体。

「ハーネス」は元々、馬具や工具の固定具を指す言葉。AIモデル単体は文章を返すだけのエンジンですが、これにツール・記憶・権限管理・エラー処理を装着して、実際に動けるエージェントに仕立てる装置全体をハーネスと呼びます。Claude Code、Cursor、Managed Agentsはすべてハーネス。2026年のAI業界で最も熱い競争領域です。

「モデルの性能差」より「ハーネスの完成度」のほうがビジネス成果を左右する時代になりました。提案するときの注目ポイント。
🎼
オーケストレーション
Orchestration

複数のAIや複数のタスクを「指揮者」が束ねて全体を動かす仕組み。

オーケストラの指揮者のように、誰が何をいつやるかを決めて全体をまとめる役割。AIエージェントの世界では、複数の専門エージェントを協調させて1つの大きな仕事を成し遂げる仕組みのことを指します。後で出てくる「マルチエージェント・オーケストレーション」がその代表例。

「複雑な業務をAIに任せたい」ときに必要になる考え方。1つのAIで全部やらせず、専門分担させるのがコツです。
🦾
自律性（オートノミー）
Autonomy

AIがどこまで「自分で判断して動けるか」の度合い。

「次は何をする？」と毎回人間に聞くAIは自律性が低い。「ゴールだけ伝えれば、あとは全部やる」AIは自律性が高い。業務に組み込むときは、どこまで任せるかを最初に設計するのが重要です。重要な意思決定は人間、ルーティンはAI、というバランス感覚が問われます。

「AIに丸投げ vs 人間が全部監視」の中間をどこに設定するか。これがAI導入コンサルの腕の見せ所です。
🛠️
ツール使用
Tool Use

AIが必要に応じて「外部のツール」を呼び出して使う能力。

電卓、検索、データベース、APIなど、AIモデル単体ではできないことを外部ツールを呼び出して補う仕組み。例えば「最新ニュースを検索する」「Excelの数式を計算する」「Slackにメッセージを送る」など。エージェント機能のほとんどはこのツール使用の応用です。

「AIに何ができるか」は、AIの賢さよりも「どんなツールが使えるか」で決まる時代になっています。
🧩
タスク分解
Task Decomposition

大きな仕事を「小さな手順」に分けて、順番に処理していく能力。

「決算資料を作って」のような曖昧で大きな指示を、AIが自分で「①データ収集 ②分析 ③グラフ作成 ④文章化 ⑤レビュー」のように具体的なステップに分解する能力。優れたエージェントの基本動作です。マルチエージェントの場合は、分解した各タスクを別のエージェントに割り振ります。

「AIに丸投げしたけど結果がイマイチ」というとき、人間側で分解を手伝ってあげると劇的に良くなることが多いです。
🔁
評価ループ
Evaluation Loop

「やってみる→評価する→改善する」を自動で繰り返す仕組み。

人間が試行錯誤するように、AIも結果を自己評価して、ダメなら別アプローチで再挑戦するループを組み込めます。後で出てくる Outcomes 機能がまさにこれ。一発で正解を出すのではなく、合格ラインを超えるまで何度もやり直すのが、信頼性の高いAIエージェントの作り方です。

「AIの出力品質を上げる」ためのテクニックの中で、最もインパクトが大きいのが評価ループの導入です。
⛰️
本番環境（プロダクション）
Production

「実際にお客さまや業務で使われる」リアルな環境のこと。

「開発環境（テスト用）」と対になる言葉。エージェントを試作するのは簡単でも、実際の業務で安定稼働させるのは別次元の難しさがあります。エラー対応、料金管理、データ保護、監査記録など、本番にはたくさんの要件が出てきます。Managed Agentsは、まさにこの本番対応を肩代わりするサービス。

「とりあえず試作」と「本番投入」の間には深い谷があります。コンサル提案でも、この違いを明確に分けて話すのがプロです。
02

Claude Managed Agents 全体像

2026年4月に発表された、Anthropicの本格AIエージェント基盤。その骨格を理解する言葉。

7 TERMS
🏗️
Claude Managed Agents PUBLIC BETA
Claude Managed Agents

「AIエージェント用の家具付きマンション」。本番運用に必要なインフラを丸ごと提供するクラウドサービス。

2026年4月8日に Anthropic が発表した、本番環境向けフルマネージドAIエージェント基盤。これまで自社でゼロから3〜6ヶ月かけて作っていた「サンドボックス・状態管理・認証・エラー復旧・コンテキスト管理」などの足場を、すべて Anthropic 側が用意してくれます。料金は実行時間1時間あたり0.08ドル（約12円）＋トークン使用料。待機時間は無料。

自社プロダクトにAIエージェントを組み込みたい開発チーム向け。Notion、Rakuten、Asana、Sentry などが初期から採用しています。
📦
サンドボックス（本番版）
Sandbox

エージェントが安全に作業できる、隔離された「砂場」環境。

Vol.01のサンドボックスと同じ考え方ですが、Managed Agentsではセッションごとに自動で用意される本格仕様。AIが任意のコードやコマンドを実行しても、本番システムに一切影響しないよう完全に隔離されます。エージェントに自由度の高い作業をさせる際の安全装置。これを自前で作るのが大変だったので、Managed Agentsの最重要価値の1つです。

「AIに業務システムを任せたいが、暴走が怖い」という不安に対する技術的回答がこれ。
⏳
セッション管理
Session Management

エージェントの「1回の仕事」を最初から最後まで管理する仕組み。

エージェントが何時間にもわたって複雑なタスクをこなすには、途中の状態を保持し、中断・再開できる仕組みが必要。「今どこまでやったか」「次は何をすべきか」を保存し、長時間タスクを安定運用するのがセッション管理の役目。Managed Agentsの中核機能です。

数時間〜数日かかる大規模分析や、夜間バッチ的な業務をAIに任せたい場合、これが堅牢かどうかが命運を分けます。
💾
状態管理
State Management

エージェントが「今どんな状況にあるか」を常に正確に把握する仕組み。

「どの変数にどの値が入っているか」「どこまでファイルを処理したか」「どんなエラーに遭ったか」など、エージェントの瞬間瞬間のスナップショットを保持する技術。長時間動くエージェントでは、この精度がそのまま信頼性に直結します。

エンジニア向け概念ですが、コンサル提案では「状態管理がしっかりしているか」が、安定したAI運用の判断基準になります。
🔐
認証情報の処理
Credential Handling

エージェントが安全にAPIキーやパスワードを扱える仕組み。

エージェントがSlack・Gmail・社内DBにアクセスするには、各サービスの認証情報が必要。これを平文で保存せず、暗号化された安全な場所から都度参照するのが本番運用の鉄則。Managed Agents はこの仕組みを最初から備えています。自前で実装すると事故の温床に。

「AIが社内システムにアクセスする」案件で、セキュリティ部門が最も気にするポイントです。
🔄
エラー回復
Error Recovery

途中でエラーが起きても、自動でリトライ・代替策・復旧をやる仕組み。

本番のエージェントは、ネットワーク切断、APIの一時障害、想定外のデータ、レート制限など、数十種類のトラブルに遭遇します。それぞれに「再試行する」「別の方法で迂回する」「人間に通知する」と適切に対処する仕組みが必要。Managed Agentsはこの機構を持っています。

「AIが途中で止まったまま誰も気づかない」事故を防ぐ重要機能。本格運用には欠かせません。
🧬
コンポーザブルAPI
Composable API

レゴブロックのように「組み合わせて独自のエージェントを作れる」API設計思想。

Managed Agents の設計思想の核。小さな部品（プリミティブ）を組み合わせて、自社の業務に合った独自のエージェントワークフローを構築できます。これにより「全部入りパッケージ」ではなく「必要な機能だけ使う」柔軟性が確保されます。Anthropic が「モデル提供会社」から「エージェント基盤提供会社」に脱皮した象徴。

「うちの業務に合わせたカスタムAIを作りたい」企業に向けて、自前開発からManaged Agentsへの移行を提案する根拠になります。
03

2026年新機能：自己改善する3つの仕組み

Code with Claude 2026 で発表された、AIエージェントを「自分で賢くなる」存在に変える3機能。

8 TERMS
🌙
Dreaming（ドリーミング）RESEARCH PREVIEW
Dreaming

AIが「夢を見ながら」過去の経験を整理して、自分で賢くなっていく機能。

人間が寝ている間に記憶を整理するのと同じ発想で、AIが過去のセッションを定期的に振り返り、繰り返しのミス・うまくいったパターン・チーム共通の好みなどを抽出。整理結果を反映するかは自動・手動を選べる安全設計です。法律業界のHarveyでは導入により完了率が約6倍に向上したと報告されています。現時点ではリサーチプレビュー（申請制）。

長期運用するエージェントを「使えば使うほど賢くなる」状態にしたい企業向け。今すぐ使うより、ニュースとして押さえておく段階。
🧠
メモリストア
Memory Store

エージェントが「学んだこと」を保存しておく、専用の記憶倉庫。

エージェントがセッションを通じて得た知識・気付き・成功パターンを保存する場所。Dreaming はこのメモリストアを定期的に整理する役割を担います。「メモリが情報をためる」「Dreamingが整理する」というセットで、自己改善型エージェントの記憶システムが完成します。

Vol.01の「メモリ機能」の本番運用版。一般ユーザーには見えない裏側の重要パーツです。
🎯
Outcomes（アウトカムズ）PUBLIC BETA
Outcomes

「合格点が出るまで、AIが自分で書き直す」仕組み。

①開発者が成功基準（ルーブリック）を定義 → ②エージェントが結果生成 → ③別のAI（grader）が採点 → ④不合格なら②に戻ってリトライ → ⑤合格なら通知。Anthropic社内テストでは、Wordファイル生成で品質+8.4%、PowerPoint生成で+10.1%の改善を確認。「採点基準を先に決めて、超えるまでAIが粘る」が公式機能化しました。

品質基準が明確なタスク（資料作成、コード生成、データ整形）で、一発で合格点に持っていきたいときに威力を発揮します。
📏
ルーブリック
Rubric

AIに「これが合格点」と先に教える、明文化された採点基準表。

もともと教育の世界で使われる言葉。Outcomes 機能では「項目ごとに何を満たせば合格か」を箇条書きで定義します。例：「①関数の長さは50行以下 ②型エラーゼロ ③テストが全通過 ④コメント率10%以上」など、計測可能な複数項目で。曖昧な「いい感じに」を排除するのがコツ。

AI出力の品質を「気合と目視」でなく、再現性ある基準で管理したいとき。コンサル・教育・士業の品質管理思考と相性◎。
👨‍⚖️
grader（採点AI）
Grader

本体のAIとは別に動く、出力の品質を採点する専任AI。

Outcomes機能の中核。「作る側のAI」と「評価する側のAI」を分けるのがポイントです。同じAIが自己評価すると甘くなりがちなので、別コンテキストで動く独立した採点AIが冷静に評価します。不合格項目を具体的に指摘し、本体AIにフィードバックして再挑戦させます。

「AIの自己採点」の限界を超える設計。複数AIによる相互チェックの最も実用的な例の1つです。
🔔
Webhook（ウェブフック）
Webhook

「タスクが終わったよ！」と、AIが外部システムに自動通知する仕組み。

Outcomes で合格判定が出た、長時間タスクが完了した、エラーで止まった——こうしたイベントを、あらかじめ登録したURLにHTTPで通知する仕組み。SlackやLINE、自社の業務システム、メールに自動連動できます。「AIに任せて、終わったらスマホで気づく」運用の要。

AIに長時間タスクを任せた後の「結果を見に行く手間」がゼロに。プッシュ型の業務通知設計が可能になります。
👑
Multi-agent Orchestration PUBLIC BETA
Multi-agent Orchestration

1人の司令塔AIが、複数の専門AIにタスクを分配して並列で働かせる仕組み。

複雑なタスクをリードエージェント（司令塔）が分解し、専門エージェントに並列委任します。サブエージェントは共有ファイルシステムで連携し、結果をリードに集約。Netflixではプラットフォームチームで本番運用中。Spiral by Every は「リードはHaiku、サブはOpus」という賢いモデル使い分けで、コストと品質を両立させています。

「1つのAIでは時間がかかる」複雑タスクを、AIチームに分業させて高速化したい場面で威力を発揮します。
📁
共有ファイルシステム
Shared Filesystem

複数のエージェントが「同じ作業スペース」でファイルを共有する仕組み。

マルチエージェントが連携する際の共通の作業机。サブエージェントAが作ったファイルをBが読んで、Cが完成させる、といった連続作業を可能にします。各エージェントは独立した文脈で動きながら、成果物は共有されるという絶妙な設計です。

「AIチームでの協働開発」を可能にする土台技術。人間のチーム作業の共有フォルダと同じ役割です。
04

マルチエージェント設計の考え方

複数AIを協調させるための設計用語。「組織図を描くようにAIをデザインする」時代に必須。

7 TERMS
🎖️
リードエージェント
Lead Agent

マルチエージェント構成での「司令塔・指揮官」役のAI。

タスク全体を受け取り、分解・分配・進捗確認・結果統合を担当する役割。人間の組織で言えばプロジェクトマネージャーやチームリーダー。Spiral by Everyの例では、リードを高速なHaiku、専門作業を高性能なOpusに割り振ることで、コストと品質の最適化を実現しています。

エージェントチームを設計するとき、最初に「リードに誰（どのモデル）を据えるか」を決めるのが基本です。
👥
サブエージェント
Subagent

特定の専門タスクに特化した、リードの下で動く実行部隊AI。

「調査担当」「コード作成担当」「レビュー担当」など、それぞれが独自のモデル・プロンプト・ツールを持ちます。会話履歴・設定・ツール権限がそれぞれ分離されているため、お互いの文脈で混乱しません。並列で同時に動けるのが強みです。

「人間の専門家チーム」と同じ感覚で、AI部隊を設計するのが2026年スタイル。役割分担の妙が成果を分けます。
🔀
並列タスク実行
Parallel Task Execution

複数のタスクを「順番に」ではなく「同時に」処理すること。

人間が1つずつ順番にこなすしかない作業を、AIエージェントなら10個同時に走らせることが可能。例えば「100社の決算分析」を10台のサブエージェントで並列処理すれば、所要時間が1/10に。Netflixの障害分析エージェントはこの方式で、何百ものビルドログを並列で精査しています。

「AIで何が変わるか」の最大級のインパクト。時間が10倍速くなる業務を見つけるのがコンサル提案の出発点です。
🚪
コンテキスト分離
Context Isolation

各エージェントが別々の「視野」を持って、お互いの文脈を混ぜない設計。

マルチエージェントの肝は各エージェントが独立した文脈で考えること。同じ文脈を共有すると、Vol.01の「コンテキスト超過」のように情報過多で混乱します。分離することで、各エージェントが自分の専門領域だけに集中できるようになります。

「AIが他の作業に引きずられて品質が落ちる」現象を防ぐための基本設計。エージェント設計の最重要原則の1つ。
🔑
ツール権限
Tool Permissions

各エージェントが「使っていい道具」「触っていいデータ」を制限する設定。

サブエージェントごとに「君は調査だけ、ファイル削除はNG」「君は読み取り専用」と権限を絞ります。これにより、万一エージェントが暴走しても被害範囲を限定可能。セキュリティとガバナンスの基本中の基本です。

企業導入の判断で、最も厳しく問われる項目。「権限管理がどうなっているか」を最初に確認するのがプロです。
📍
チェックポイント
Checkpointing

長時間タスクの途中で「セーブポイント」を作り、中断・再開できる仕組み。

数時間〜数日かかる大きな仕事の途中で、定期的にエージェントの状態を保存。万一エラーで止まっても、最初からやり直さず、保存ポイントから続行できます。ゲームのセーブと同じ発想。長時間タスクの安定運用に必須の仕組みです。

「夜間バッチ」「大量データ処理」「長文ドキュメント生成」など、時間のかかる仕事をAIに任せるすべての場面で重要。
🤝
エージェント間通信
Agent Communication

エージェント同士が「相談・依頼・報告」をやりとりする仕組み。

リードがサブに「これやって」と依頼し、サブが「終わったよ」と報告。途中で「分からないから教えて」「もう少し情報ちょうだい」とやりとりする。これらの会話を構造化して効率化する仕組みが、Managed Agentsには組み込まれています。

人間のチームコミュニケーションをAIに移植する考え方。「報連相」がAIにも必要、という発想です。
05

本番運用に必要な仕組み

エージェントを「動くだけ」から「企業で本格運用できる」状態へ。ガバナンス・コスト・SLAの言葉。

7 TERMS
🖥️
Claude Console
Claude Console

エージェントの挙動を「可視化・追跡」する管理者ダッシュボード。

どのエージェントが、何を、いつ、なぜ実行したかをすべて可視化・追跡できる管理画面。マルチエージェントの場合、リードとサブそれぞれの動きを時系列で確認可能。コンプライアンス対応や、エラー発生時のデバッグに必須。API課金・利用量のモニタリングもここから行います。

「AI利用をブラックボックスにせず、説明責任を果たす」企業に欠かせないツール。監査対応の中核。
📜
監査ログ
Audit Log

「いつ・誰が・どのエージェントに・何をさせたか」のすべての記録。

企業や規制業界での導入には事細かな記録が法的に必要。Managed Agentsは設計段階から監査ログを前提に作られており、必要に応じて長期保存・抽出が可能です。金融、医療、法務など、規制が厳しい業界の導入条件になっています。

「うちは監査が厳しいからAIは無理」という企業に対して、Managed Agents は1つの回答になります。
⚖️
コンプライアンス
Compliance

法令・社内規程・業界ルールを守ってAIを運用すること。

個人情報保護法、GDPR、業界ガイドライン、社内承認フローなど、企業がAIを本格運用するには守るべきルールが山ほどあります。Managed Agentsは、これらの対応がしやすい設計になっています（権限管理、監査ログ、データ保護など）。

大企業案件でAI導入を提案するとき、機能の話より先にコンプライアンス対応の話が来ることが多いです。
💰
従量課金
Usage-based Pricing

「使った分だけ払う」料金体系。AIエージェントの世界では主流。

Managed Agentsは実行時間1時間あたり0.08ドル、待機時間は無料、Claudeモデルの使用料は別途トークン単位。固定費なく始められる反面、使用量が読みづらい難点もあります。コスト管理のため、利用上限設定・通知設定が重要です。

経営層への提案で「いくらかかるの？」と聞かれたとき、従量課金の見立てを出すのがコンサルの腕の見せ所。
🚦
レート制限
Rate Limit

「一定時間あたりの呼び出し回数」の上限。本番運用ではコスト管理の要。

「1分間に100リクエストまで」「1日10,000リクエストまで」など、使い過ぎを防ぐ上限。Vol.01でも紹介しましたが、本番運用では「想定外の利用が暴走してコスト爆発」を防ぐ重要な仕組みになります。Anthropicは2026年5月、Pro/Maxユーザーの5時間制限を10時間に倍増しました。

「AI導入したら月の請求が10倍になった」という事故を防ぐための保険。設計時に必ず織り込みます。
📊
SLA（サービス品質保証）
Service Level Agreement

「このサービスは99%以上稼働します」など、提供品質の約束。

企業がクラウドサービスを採用する判断基準。稼働率、応答速度、サポート対応時間などが契約で定められています。Managed Agentsはエンタープライズ契約でSLAが提供され、自前運用では難しい高い信頼性を担保できます。

「自社で作る」vs「Managed Agentsを使う」を比較するときの重要評価軸の1つ。
🛡️
ガバナンス
Governance

組織全体で「AIをどう使うか、何を許可するか」を統制する仕組み。

「どの部署にどの権限を渡すか」「どんな業務に使ってよいか」「リスクをどう管理するか」という、会社レベルのAI利用ポリシー。Managed Agents・Claude Console・監査ログを組み合わせることで、組織的なガバナンスが実現可能になります。

経営層やCISO（最高情報セキュリティ責任者）と話すときの最重要キーワード。「ガバナンスを担保できるか」が導入可否を決めます。
06

業界別エージェント実例（Claude Finance）

2026年5月発表の Claude Finance を例に、業界特化エージェントの実態を知る。

5 TERMS
💼
Claude Finance GA
Claude Finance

金融業界向けに、すぐ使える10種類のAIエージェントテンプレート集。

2026年5月5日発表。投資銀行・資産運用・保険業界の典型業務をカバーする、「skills（業務知識）＋connectors（データアクセス）＋subagents（専門サブAI）」の3点セットで提供される10種類のテンプレート。Goldman Sachs、Visa、Citi、AIGなど大手金融機関も導入を進めています。

業界特化エージェントの先駆け。今後、医療・法務・小売など、他業界版が出てくる流れの第一弾です。
📑
ピッチビルダー
Pitch Builder

投資銀行のM&Aプレゼン資料を自動で作るエージェント。

Claude Financeの目玉機能の1つ。類似企業選定、財務分析、評価倍率計算、スライド構成を自動化します。これまで若手アナリストが徹夜で作っていた業務を、エージェントが下書きまで持っていく形に。最終チェックは人間（Human in the Loop）。

「業界特化エージェントの威力」を最も実感できる例。HUMMERさん的にはコンサル提案資料の自動化に応用可能。
🔍
KYCスクリーナー
KYC Screener

顧客の身元確認・反社チェックを自動化するエージェント。

KYC（Know Your Customer）は金融機関の必須業務。Claude Financeのエージェントは、顧客情報を複数の公開DB・制裁リスト・反社リストと照合し、リスク評価レポートを自動生成。コンプライアンス担当者の負荷を大幅に軽減します。

金融以外でも、不動産・人材・特定取引など「与信が必要な業界」全般に応用可能なパターンです。
📕
Cookbook（クックブック）
Cookbook

「料理レシピ」のように、エージェントの完全実装例を提供する公式リソース。

Anthropic公式が提供する、動くエージェントの参照アーキテクチャ。Claude Financeの10種類のエージェントも、それぞれcookbookとして公開されており、各社はこれをコピー→自社ルールに合わせて改変するスタイルで導入できます。

ゼロから設計するより、cookbookを起点にした方が圧倒的に早い。「車輪の再発明をしない」のがAI時代のスピード感です。
🏆
業界ベンチマーク
Industry Benchmark

業界特化AIの性能を客観的に測る共通の評価基準。

Claude Finance は Vals AI Finance Agent ベンチマークで64.37%という業界トップの成績を記録（Claude Opus 4.7との組み合わせ時）。「うちのAIは賢い」と主観で言うのではなく、業界共通の物差しで証明するのが2026年スタイルです。

クライアントへのAI提案で「他社AIと比べてどうなの？」と聞かれたときの根拠になります。
