00

MCPとは何か

APIとの違いがわかれば、MCPの価値が一気に理解できます。USBハブで全部わかります。

CONCEPT

MCP

Model Context Protocol（モデル・コンテキスト・プロトコル）

USBハブのように、MCPという共通規格があればClaude Codeはあらゆるサービスに同じ方法で接続・操作できる

USBを思い浮かべてください。マウスでも、キーボードでも、USBメモリでも、USBという共通規格があれば1つのポートに何でもつなげます。つなぐたびに新しい変換器を作る必要がありません。

MCPはまさにこの「AIのためのUSB規格」です。Anthropicが2024年11月に公開したオープン規格で、Claude Codeがどのサービスに対しても同じ方法で接続・操作できるようになります。個別にAPIの仕様を覚えたり、コードを書いたりする必要がなくなります。

APIとの最大の違いは「誰が操作するか」です。APIは「人間がプログラムを書いて呼び出す」仕組み。MCPは「AIエージェントが自律的にツールを選択・実行する」仕組みです。「Notionのこのページを要約して」と日本語で言えば、Claude CodeがMCP経由でNotionに接続し、自動でページを取得・要約してくれます。

API vs MCP 違い早見表

Vol.04（API）とVol.05（MCP）の違いをまとめました。クライアントへの説明にも使えます。

QUICK REFERENCE
操作する主体
API：人間がコードを書いて呼び出す　／　MCP：AIエージェントが自律的に判断・実行する
コードの必要性
API：ある程度の開発知識が必要　／　MCP：自然言語の指示だけでOK（コード不要）
接続方法の標準化
API：サービスごとに異なる仕様を学ぶ必要がある　／　MCP：共通規格なので同じ方法で全サービスに接続
権限・セキュリティ
API：開発者が個別に実装する　／　MCP：権限管理・認証が標準化されており安全
活用シーン
API：自動化スクリプト・バックエンド開発・定型処理　／　MCP：AIエージェントの自律業務・対話型操作
例：Slackへの投稿
API：コードでSlack APIを呼び出すプログラムを書く　／　MCP：「#generalに投稿して」と言うだけで完了
将来性
API：引き続き重要な基盤　／　MCP：AIエージェント時代の標準規格として急速に普及中

MCPが変えるのは「AIへの頼み方」だけじゃない

APIを知ることで「このツールを自動化できる」とわかりました。MCPを知ることで「AIに任せられる」に変わります。

この違いは、自動化の設計者（人間）とAIの関係を根本的に変えます。人間がコードを書いて操作するのではなく、人間が「何をしてほしいか」を伝えれば、AIが手段を選んで実行する時代に入っています。

Vol.01〜05の5冊を通じて、AIを「使う側」から「設計する側」への道筋が見えてきたはずです。次のステップは、この知識を実際の業務やクライアント提案の場に使うことです。
